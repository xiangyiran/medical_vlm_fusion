# Medical VLM Fusion

This project converts the supplied IU X-ray preprocessing, main fusion, ablation, and I2T visualisation notebooks into a Colab-oriented paper source layout. The model definitions, loss functions, data split, training loops, metrics, comments, and hyperparameter values are retained inside the modular `src/medical_vlm/` package. Model selection is passed explicitly as command-line parameters by the notebooks.

## Source layout

```text
src/
├── main_experiment.py                 # Small main-study CLI entry
├── ablation_experiment.py             # Small ablation CLI entry
├── preprocessing/
│   └── preprocess_iu_xray_chexpert14.py
└── medical_vlm/
    ├── config.py                      # Original constants and Drive paths
    ├── data.py                        # Dataset, split, processors, DataLoaders
    ├── utils.py                       # Seeds, pooling, AMP helpers
    ├── models/
    │   ├── encoders.py                # Shared encoders and two-tower base
    │   ├── image_only.py
    │   ├── text_only.py
    │   ├── concat_fusion.py
    │   ├── average_fusion.py
    │   ├── gated_fusion.py
    │   ├── self_attention_fusion.py
    │   ├── bidirectional_cross_attention.py
    │   ├── alignment_loss.py
    │   └── bicross_ablation.py
    ├── training/
    │   ├── engine.py                  # Train, validation, and test loops
    │   ├── metrics.py                 # Multi-label metrics
    │   ├── checkpointing.py           # Drive checkpoints and result JSON
    │   └── profiling.py               # Parameters, GFLOPs, latency, memory
    ├── experiments/
    │   ├── main.py                    # Main model registry/orchestration
    │   └── ablation.py                # Ablation registry/orchestration
    └── visualization/
        └── i2t.py                     # I2T heatmaps and token attention
```

There is no `scripts/` layer. The training notebooks call the two small experiment entries directly, while the result notebook imports the I2T functions from `src/medical_vlm/visualization/i2t.py`.

## Required seeds

The notebook entry points execute seeds `42`, `95`, and `1024`. Each Python invocation receives one explicit `--seed`, `--model`, and `--action`; the remaining hyperparameters are unchanged.

## Google Drive project artifacts

All persistent experiment outputs generated by preprocessing, training, testing, aggregation, and visualisation stay inside the project folder:

```text
/content/drive/MyDrive/Dissertation/medical_vlm_fusion/artifacts/
├── data/
│   └── iu_xray_chexpert14/
├── checkpoints/
│   ├── exp_seed_42/
│   ├── exp_seed_95/
│   └── exp_seed_1024/
└── results/
    ├── exp_seed_42/
    ├── exp_seed_95/
    ├── exp_seed_1024/
    └── three_seed_average/
```

The repository does not define any local experiment-output directory. The `artifacts/` directory is ignored by Git because generated datasets and checkpoints should not be committed to a paper-source repository.

Downloadable caches are intentionally left in Colab's default temporary local storage. Kaggle data and pretrained model weights are therefore reused within one runtime session and downloaded again after the runtime is reset.

## Colab notebooks

Copy this project to `/content/drive/MyDrive/Dissertation/medical_vlm_fusion`, select an A100 runtime, and run these notebooks in order:

1. `notebooks/01_main_training_and_testing.ipynb` mounts Drive, installs dependencies, runs preprocessing, and provides one independent cell for each of the 21 main model/seed jobs.
2. `notebooks/02_ablation_training_and_testing.ipynb` provides one independent cell for each of the 21 reference/ablation model/seed jobs.
3. `notebooks/03_results_display.ipynb` displays preprocessing outputs, three-seed mean main/ablation results, paper plots, and an imported I2T visualisation for the seed and sample selected in its execution cells.

The Python entries called directly by the notebooks have the form:

```bash
python src/main_experiment.py --seed 42 --model image_only --action train
python src/ablation_experiment.py --seed 42 --model bicross_i2t_only --action train
```

`TRAIN_MODEL_FLAGS` is not used. The notebooks explicitly determine the order of models and seeds.

## Results

Open `notebooks/03_results_display.ipynb` after both experiment notebooks finish. It reads the three Drive result folders and computes arithmetic means across the three seed-level metrics. I2T heatmaps remain labelled by seed because they are sample/checkpoint-specific rather than scalar metrics.

## Preprocessing

`src/preprocessing/preprocess_iu_xray_chexpert14.py` is migrated from the supplied preprocessing notebook. Its report selection, rule labeler, uncertainty policy, frontal-image selection, and output filenames are unchanged. Processed CSV and metadata files are stored under the project's `artifacts/data/` directory, while the downloadable Kaggle dataset remains in Colab's temporary local cache.
